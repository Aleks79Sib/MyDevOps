# Полное руководство по проверке сервера на майнеры (Ubuntu/Debian)

Это пошаговая инструкция поможет вам выявить и обезвредить скрытые майнеры криптовалют, а также другие вредоносные программы на вашем Linux-сервере. Она основана на реальных методах, которые мы применили в нашем диалоге.

---

## 📌 Признаки заражения майнером

Прежде чем проверять, обратите внимание на симптомы:

- **Высокая загрузка CPU** (особенно в простое) — проверяйте через `htop` или `top`.
- **Постоянный шум кулера** или нагрев процессора.
- **Необъяснимые сетевые подключения** к неизвестным IP на портах: 3333, 4444, 5555, 8080, 14444, 7777 и т.п.
- **Появление подозрительных файлов** в `/tmp`, `/dev/shm`, `/var/tmp`.
- **Неизвестные процессы** с именами, похожими на системные (например, `[kworker]`, `[kthreadd]`, но с подозрительными аргументами).
- **Пропадание свободного места** на диске (майнеры могут создавать временные файлы).

Если вы наблюдаете хотя бы один из признаков — немедленно приступайте к проверке.

---

## 🔍 Шаг 1. Базовая проверка текущих процессов

Запустите `top` в режиме сортировки по CPU:

```bash
top -o %CPU
```

Нажмите `q` для выхода. Обратите внимание на процессы, потребляющие > 20% CPU, особенно если они запущены от пользователей `nobody`, `daemon` или имеют странные имена.

Или используйте `ps` с фильтром по известным именам майнеров:

```bash
ps aux | grep -E -i "miner|xmrig|stratum|nicehash|cpuminer|kawpow|ethminer|t-rex|phoenixminer|lolminer|teamred|gminer|nanominer|bminer|nheqminer|zec|claymore|ewbf|dstm|ccminer|sgminer|bfgminer|cgminer|antminer|asic|bitmain|innosilicon|whatsminer|microbt|kworker|kthreadd|systemd-network|systemd-resolve" | grep -v grep
```

---

## 🌐 Шаг 2. Проверка сетевых подключений

Просмотрите все активные (установленные) соединения:

```bash
sudo ss -tupn | grep ESTAB
```

Ищите внешние IP-адреса и порты, которые не относятся к вашим сервисам (например, если вы не используете майнинг-пулы). Часто майнеры подключаются к пулам по портам:
- 3333, 4444, 5555, 7777, 8080, 14444, 45560, 13531 и т.п.

Также проверьте, какие порты слушаются (входящие) — майнеры редко слушают порты, но могут открывать бэкдоры:

```bash
sudo ss -tulpn
```

Сравните со списком ваших известных сервисов.

---

## 🗂️ Шаг 3. Проверка скрытых файлов и каталогов

Майнеры часто распаковываются в `/tmp`, `/dev/shm`, `/var/tmp`, `/run`, `/usr/local/bin` или создают скрытые каталоги в домашней папке пользователя.

```bash
ls -la /tmp /dev/shm /var/tmp | grep -E "\.(sh|py|bin|xmr|stratum)|[0-9a-f]{8,}"
```

Проверьте исполняемые файлы в системных директориях на предмет недавних изменений:

```bash
find /usr/bin /usr/local/bin /bin /sbin -type f -mtime -7 -ls 2>/dev/null
```

---

## ⏰ Шаг 4. Проверка автозапуска

Майнеры закрепляются через cron, systemd или скрипты автозагрузки.

### 4.1. Проверка cron (для всех пользователей)

```bash
crontab -l
sudo crontab -l
for user in $(cut -f1 -d: /etc/passwd); do sudo crontab -u $user -l 2>/dev/null; done
```

Ищите команды с `curl`, `wget`, `bash -c`, `python -c`, `ssh -R` или подозрительные скрипты из `/tmp`.

### 4.2. Проверка systemd-сервисов и таймеров

```bash
systemctl list-units --type=service --all | grep -E "miner|stratum|tunnel|auto"
systemctl list-timers --all
```

Особое внимание на сервисы с нестандартными именами (например, `update-systemd`, `sys-stat`, `syslog-ng`). Проверьте их содержимое:

```bash
systemctl cat <имя_сервиса>
```

### 4.3. Проверка скриптов в ~/.profile, ~/.bashrc, ~/.bash_login

```bash
grep -E "curl|wget|bash|python|ssh" ~/.profile ~/.bashrc ~/.bash_login ~/.ssh/rc 2>/dev/null
```

### 4.4. Проверка systemd --user (для текущего пользователя)

```bash
systemctl --user list-units --type=service --all
```

## 📋 Шаг 5. Анализ системных логов

Используйте `journalctl` для поиска подозрительных событий за определённое время (например, когда была замечена нагрузка):

```bash
sudo journalctl --since "2026-07-14 02:45:00" --until "2026-07-14 03:15:00" | grep -E "fork|exec|Started|Starting|CRON|systemd"
```

Ищите аномально частые перезапуски сервисов, запуски неизвестных команд, ошибки при выполнении.

Логи SSH (попытки входа):

```bash
sudo grep "Failed password" /var/log/auth.log
sudo grep "Accepted" /var/log/auth.log
```

## 🛠️ Шаг 6. Специализированные инструменты

### 6.1. rkhunter и chkrootkit

Установите и запустите базовые сканеры руткитов:

```bash
sudo apt install rkhunter chkrootkit
sudo rkhunter --check
sudo chkrootkit
```

Эти инструменты могут обнаружить известные майнеры и бэкдоры.

### 6.2. ClamAV (антивирус)

Хотя ClamAV не специализируется на майнерах, он может найти некоторые сигнатуры.

```bash
sudo apt install clamav clamav-daemon
sudo freshclam
sudo clamscan -r / --exclude-dir=/sys --exclude-dir=/proc --exclude-dir=/dev --exclude-dir=/run -i
```

### 6.3. Использование утилиты `lsof` для поиска открытых файлов

```bash
sudo lsof | grep -E "miner|xmrig|stratum"
```

### 6.4. Проверка процессов с помощью `strace` (если нашли подозрительный PID)

```bash
sudo strace -p <PID> -s 200 -e trace=network,file
```

## 📊 Шаг 7. Мониторинг ресурсов в исторической перспективе

Установите `sysstat` и проанализируйте нагрузку за предыдущие дни:

```bash
sudo apt install sysstat
sar -u -f /var/log/sysstat/sa??
```

Это покажет нагрузку CPU по часам и минутам — вы сможете сопоставить пики с другими логами.

---

## 🧹 Шаг 8. Если обнаружен майнер

1. **Остановите процесс** — `sudo kill -9 <PID>`.
2. **Удалите файл** — `sudo rm -rf /path/to/executable`.
3. **Удалите скрипты автозагрузки** (cron, systemd, .bashrc).
4. **Проверьте SSH-ключи** — `cat ~/.ssh/authorized_keys`, удалите чужие.
5. **Смените пароли** всех пользователей и ключи доступа.
6. **Перезагрузите сервер**, убедитесь, что процесс не запустился снова.
7. **Обновите систему** — `sudo apt update && sudo apt upgrade -y`.

---

## 🛡️ Шаг 9. Предотвращение повторного заражения

- Отключите вход по паролю в SSH (используйте только ключи).
- Используйте нестандартный порт SSH.
- Ограничьте доступ по IP (с помощью `ufw` или `iptables`).
- Регулярно обновляйте все пакеты.
- Следите за входящими соединениями через `fail2ban`.
- Используйте `auditd` для мониторинга изменений критичных файлов.
- Настройте уведомления о высокой нагрузке (например, через Zabbix, Netdata).
- Не запускайте сервисы от пользователя `root`, используйте непривилегированных пользователей.

## ✅ Шаг 10. Регулярный аудит

Рекомендуется раз в неделю прогонять базовые проверки:

```bash
# Скрипт для еженедельного аудита (можно добавить в cron)
#!/bin/bash
echo "=== CPU Top ==="
top -b -n 1 | head -20
echo "=== Connections ==="
ss -tupn | grep ESTAB | head -20
echo "=== Recent binaries ==="
find /tmp /dev/shm /var/tmp -type f -mtime -7 -ls
echo "=== Cron ==="
crontab -l 2>/dev/null
```

Сохраняйте вывод для сравнения.

## 🏁 Заключение

Следуя этому руководству, вы сможете эффективно обнаруживать майнеры и другие угрозы. Помните, что главное — систематичность: проверяйте все уровни (процессы, сеть, автозагрузку, файлы). Если вы подозреваете взлом, но не можете найти причину, возможно, стоит переустановить систему и восстановить данные из надёжных бэкапов.

Надеюсь, это руководство поможет вам поддерживать сервер в чистоте и безопасности. Если у вас остались вопросы или нужны дополнительные разъяснения — обращайтесь!
