## Part 3. Утилита **iperf3**

[утилита iperf](./docs/RUS/iperf3_RUS.md)

### 3.1. Скорость соединения
- Переведём скорость :
  - 8 Mbps = 1 MB/s, (1 байт = 8 бит, 8/8) 
  - 100 MB/s = 819200 Kbps, (1 MB = 1024 KB, 1 байт = 8 бит, 100 * 1024 * 8 = 819200)
  - 1 Gbps = 1000 Mbps в десятичной системе. (1 Gb = 1000 Mb (или 1024 Mb в двоичной системе))

### 3.2. Утилита **iperf3**
*iperf3* - это утилита командной строки для измерения пропускной способности сети между двумя устройствами. Она позволяет оценить скорость передачи данных между клиентским и серверным устройствами.
- Установим утилиту **iperf3**
`sudo apt install iperf3 -y`
- Запускаем на ws1 в режиме сервера с выводом результата в MB/s: iperf3 -s -f M
![Report iperf3 ws1](./docs/images/2_3_test_iperf3-ws1_28_10_2025_12_56_32.png)
- Запускаем на ws2 в режиме клиента: iperf3 -c 192.168.100.10
![Report iperf3 ws2](./docs/images/2_3_test_ws2_28_10_2025_12_54_46.png)

## Part 4. Сетевой экран

[Firewall](./docs/RUS/firewall_RUS.md)

### 4.1. Утилита **iptables**

- Создаем файл */etc/firewall.sh*, имитирующий файрвол, на ws1 и ws2:
`sudo nano /etc/firewall.sh`

[firewall.sh](./configs/firewall.sh)

```shell
#!/bin/sh

# Удаление всех правил в таблице «filter» (по умолчанию).
iptables -F
iptables -X
```
- Добавили в файл подряд следующие правила:
  - 1) На ws1 примени стратегию, когда в начале пишется запрещающее правило, а в конце пишется разрешающее правило (это касается пунктов 4 и 5). \
![report nano ws1](./docs/images/4_1_nano-ws1_28_10_2025_20_56_55.png)
  - 2) На ws2 примени стратегию, когда в начале пишется разрешающее правило, а в конце пишется запрещающее правило (это касается пунктов 4 и 5). \
![report nano ws2](./docs/images/4_1_nano_ws2_28_10_2025_20_57_43.png)
  - 3) Открой на машинах доступ для порта 22 (ssh) и порта 80 (http).
  - 4) Запрети *echo reply* (машина не должна «пинговаться», т. е. должна быть блокировка на OUTPUT).
  - 5) Разреши *echo reply* (машина должна «пинговаться»).

- Запустили файлы на обеих машинах командами: `chmod +x /etc/firewall.sh` \ `/etc/firewall.sh`. \
![report ping ws1](./docs/images/4_1_ping_ws1_28_10_2025_21_07_51.png) \

![report ping ws2](./docs/images/4_1_ping_ws2_28_10_2025_21_09_44.png)

*Объяснение разницы между стратегиями:*
- ws1 (запрет → разрешение):

  - Правило 4 (DROP) идёт первым
  - Правило 5 (ACCEPT) идёт вторым

**Результат:** *iptables применяет правила сверху вниз и останавливается на первом совпадении* \
Пакеты echo-reply блокируются первым правилом (DROP) \
Второе правило (ACCEPT) никогда не выполняется \
*Машина НЕ пингуется (не отправляет echo-reply)*

- ws2 (разрешение → запрет):

  - Правило 5 (ACCEPT) идёт первым
  - Правило 4 (DROP) идёт вторым
Пакеты echo-reply разрешаются первым правилом (ACCEPT)
Второе правило (DROP) никогда не выполняется
*Машина пингуется (отправляет echo-reply)*

**Вывод**: *В iptables важен порядок правил. Применяется первое подходящее правило, остальные игнорируются.*

Почему для адреса 10.10.0.0/\[маска сети\] был выбран маршрут, отличный от 0.0.0.0/0, хотя он попадает под маршрут по умолчанию.

- **Ответ**:
В Linux маршрутизация работает по принципу longest prefix match (совпадение самой длинной маски). \
Маршрут 10.10.0.0/18 имеет маску /18 (более специфичная) \
Маршрут 0.0.0.0/0 имеет маску /0 (менее специфичная, default) \
Когда пакет идёт к адресу из сети 10.10.0.0/18 (например, 10.10.0.5): \
Система проверяет все маршруты \
Находит два совпадения: \
10.10.0.0/18 — совпадает, маска /18 \
0.0.0.0/0 — совпадает (любой адрес), маска /0 \
Выбирает более специфичный (с большей маской): 10.10.0.0/18 \
Пакет отправляется напрямую через dev enp0s8, без шлюза.

- **Вывод**: *Специфичные маршруты имеют приоритет над маршрутом по умолчанию. Локальная сеть доступна напрямую, без роутера*.


### 5.5. Построение списка маршрутизаторов

Пример вывода утилиты **traceroute** после добавления шлюза:
```
1 10.10.0.1 0 ms 1 ms 0 ms
2 10.100.0.12 1 ms 0 ms 1 ms
3 10.20.0.10 12 ms 1 ms 3 ms
```
- Запустим на r1 команду дампа:
`tcpdump -tnv -i eth0`

![Report tcpdump r1](./docs/images/5_5_traceroute_VirtualBox_r1_30_10_2025_14_13_40.png)

- При помощи утилиты **traceroute** построили список маршрутизаторов на пути от ws11 до ws21.\
`traceroute 10.20.0.10`

![Report tcpdump r1](./docs/images/5_5_VirtualBox_ws11_30_10_2025_14_14_10.png)

- Принцип работы traceroute (для отчёта):
traceroute использует поле TTL (Time To Live) в IP-пакетах: 

  - Первый пакет: TTL = 1\
ws11 отправляет пакет с TTL=1\
r1 получает пакет, уменьшает TTL на 1 (становится 0)\
r1 отбрасывает пакет и отправляет ICMP Time Exceeded обратно ws11\
ws11 узнаёт IP первого роутера: 10.10.0.1

  - Второй пакет: TTL = 2
ws11 отправляет пакет с TTL=2\
r1 получает, уменьшает до TTL=1, пересылает дальше\
r2 получает, уменьшает до TTL=0, отбрасывает\
r2 отправляет ICMP Time Exceeded обратно\
ws11 узнаёт IP второго роутера: 10.100.0.12

  - Третий пакет: TTL = 3
Доходит до ws21\
ws21 отвечает ICMP Port Unreachable (или ICMP Echo Reply если используется -I)\
ws11 узнаёт, что достиг цели: 10.20.0.10

- **Вывод**: *traceroute постепенно увеличивает TTL, чтобы каждый роутер на пути "отозвался" сообщением ICMP Time Exceeded*.
